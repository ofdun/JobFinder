## ADR-001. Выбор реляционной модели хранения данных

**Контекст.** База данных сервиса поиска работы должна хранить сведения о соискателях, работодателях, резюме, вакансиях, откликах и справочниках. Для выбора модели хранения определены три критерия:

- **К1** — поддержка неиерархических связей между сущностями;
- **К2** — обеспечение целостности данных для предотвращения противоречивой информации об одной и той же сущности;
- **К3** — поддержка связей типа «многие ко многим».

**Рассмотренные альтернативы.** Иерархическая модель, сетевая модель, модель на основе инвертированных списков, реляционная и постреляционная модели.

**Решение.** Использовать реляционную модель хранения данных.

**Обоснование.** По результатам сравнения реляционная модель соответствует всем трём критериям. Её структурная составляющая описывает данные как нормализованные отношения. Целостная составляющая предусматривает целостность сущностей и ссылочную целостность: записи должны быть различимы, а значения внешних ключей --- соответствовать ключам связанных записей либо быть неопределёнными, если это допускается.

Основание ADR-001: `rpz.pdf`, разделы 1.5–1.6 (стр. 12–16 документа).
