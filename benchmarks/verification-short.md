| Требование 3. Собственный инструмент допустим | [run.py](./run.py), [report.py](./report.py), [topk_view.py](./topk_view.py); `python3 -m unittest discover -s benchmarks -p 'test_*.py'` — 24 проверки. |

| Требование 5. Несколько сценариев | `random`, `ascending`, `descending`; N = 1 000 / 10 000 / 100 000; K = 20 / 100 / N÷2; 54 комбинации + baseline на прогон. |
| Требование 6. Отдельный образ на прогон, одинаковые условия | [Run.Dockerfile](./Run.Dockerfile), [manifest.json](./results/20261012T203308Z-52fb4024/manifest.json): отдельные image/container ID, общий base image, одинаковые seed/JVM/ресурсы. 100 trials выполняются внутри каждого JVM-прогона. |

| Требование 8b. Распределение по перцентилям по числу операций | [diagnostics.html](./results/20261012T203308Z-52fb4024/diagnostics.html) → «Подробная статистика» → порядок → «Перцентили»: доля индивидуальных операций с длительностью не выше заданной; все измерения, не средние trials. |
| Требование 8c. Гистограмма | [diagnostics.html](./results/20261012T203308Z-52fb4024/diagnostics.html) → «Подробная статистика» → порядок → «Гистограмма»: 24 общих линейных интервала, все операции, обе реализации на одном графике. |
| Требование 8d. p0.5 / p0.75 / p0.9 / p0.95 / p0.99 | HTML → вкладки p50 / p75 / p90 / p95 / p99, общая шкала; «Подробная статистика» и «Накладные расходы» раскрыты сразу. Точные значения — [summary.json](./results/20261012T203308Z-52fb4024/summary.json). |
| Требование 8e. Время выполнения | HTML: весь запуск со сборкой и каждый контейнер; длительности фаз — diagnostics.html; [manifest.json](./results/20261012T203308Z-52fb4024/manifest.json), CSV. |
