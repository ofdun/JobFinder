| Пункт PDF | Файл / проверка / команда (из `project`) |
| --- | --- |
| Исходное задание | ТИОПО, лабораторная работа №3, обе страницы. |
| Примечание 1. Микробенчмаркинг | [VacancyBenchmark.java](./src/com/ofdun/jobfinder/benchmark/VacancyBenchmark.java): отбор K вакансий из списка в памяти; без HTTP, Spring и БД. |
| Задание. Сравнение двух объектов | `fullSort()` против `topK()`: полная сортировка против ограниченной `PriorityQueue`; одинаковый результат, зарплата по убыванию, ID по возрастанию при равной зарплате. |
| Задание, варианты 1–7 | Выбран вариант 7: два алгоритма одной операции. Остальные варианты — альтернативы. |
| Вариант 7. Рекомендуемый диапазон 100 ns–50 ms | `summary.json` после локального запуска: `min_ns`, `max_ns`, `below_100ns`, `above_50ms`. Выбросы сохраняются, baseline отдельно. |
| Требование 1. ≥100 испытаний и статистика | `python3 benchmarks/run.py`: 100 trials × 4 операции на комбинацию, два JVM-прогона; mean, SD, min/max и перцентили в `summary.json` (локально после запуска). |
| Требование 2. Warmup / teardown | `measure()`: warmup ≥64 операций и ≥250 ms; teardown — 16 tail-операций. Обе фазы исключены из перцентилей. |
| Требование 3. Собственный инструмент допустим | [run.py](./run.py), [report.py](./report.py), [topk_view.py](./topk_view.py); `python3 -m unittest discover -s benchmarks -p 'test_*.py'` — проверки расчётов и данных. |
| Требование 4. Одно ядро CPU | `--cpus=1 --cpuset-cpus=0 -XX:ActiveProcessorCount=1`; фактические ограничения — `manifest.json` (локально после запуска). |
| Требование 5. Несколько сценариев | `random`, `ascending`, `descending`; N = 1 000 / 10 000 / 100 000; K = 20 / 100 / N÷2; 54 комбинации + baseline на прогон. |
| Требование 6. Отдельный образ на прогон, одинаковые условия | [Run.Dockerfile](./Run.Dockerfile), `manifest.json` (локально после запуска): отдельные image/container ID, общий base image, одинаковые seed/JVM/ресурсы. 100 trials выполняются внутри каждого JVM-прогона. |
| Требование 7. Оценка overhead, в идеале ≤4–5 ns | Локальный `index.html` → «Накладные расходы»: статистика harness. Из результатов ничего не вычитается; сравнить измеренное значение с ориентиром ≤5 ns. |
| Требование 8a. Измеряемая величина во времени | `diagnostics.html` (локально после запуска) → «Подробная статистика» → порядок → «Во времени»: среднее каждого trial, время относительно первого измерения алгоритма; полные точки — CSV. |
| Требование 8b. Распределение по перцентилям по числу операций | `diagnostics.html` (локально после запуска) → «Подробная статистика» → порядок → «Перцентили»: доля индивидуальных операций с длительностью не выше заданной; все измерения, не средние trials. |
| Требование 8c. Гистограмма | `diagnostics.html` (локально после запуска) → «Подробная статистика» → порядок → «Гистограмма»: 24 общих линейных интервала, все операции, обе реализации на одном графике. |
| Требование 8d. p0.5 / p0.75 / p0.9 / p0.95 / p0.99 | HTML → вкладки p50 / p75 / p90 / p95 / p99, общая шкала; «Подробная статистика» и «Накладные расходы» раскрыты сразу. Точные значения — `summary.json` (локально после запуска). |
| Требование 8e. Время выполнения | HTML: весь запуск со сборкой и каждый контейнер; длительности фаз — diagnostics.html; `manifest.json` (локально после запуска), CSV. |
| Требование 8f. Счётчики с warmup / teardown | Локальный `diagnostics.html` → порядок → «Фазы и счётчики»; численные данные — `summary.json`, поле `phases`. |
| Корректность сравнения | `verify()`: эталонный результат, равные зарплаты, пустой ввод, K=0/1/N/>N, отрицательный K, все размеры/порядки, 32 seed, неизменность входного списка. Выполняется при сборке образа и перед каждым прогоном. |
| Полнота измеряемой операции | Копирование/рабочие структуры, проход, сортировка и создание итогового списка входят в замер; фикстуры и вывод CSV — вне замера. |
| Повторить исследование | `python3 benchmarks/run.py`; новый каталог и путь к HTML печатаются в консоли. `--smoke` — только пробная проверка, не итоговые результаты. |
| Пересобрать только HTML | `python3 benchmarks/report.py benchmarks/results/<каталог-запуска>`. |
